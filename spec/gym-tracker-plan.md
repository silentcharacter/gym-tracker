# Gym Tracker — Telegram Mini App

План реализации для работы в Claude Code.

## 1. Цель

Одно приложение (Telegram Mini App) решает две задачи:

1. **Учёт блоков тренировок у тренера.** Блок состоит ровно из 12 тренировок. Тренировки чередуются по 5 группам мышц. Отметка тренировки делается одним кликом: проставляются текущая дата и следующая по очереди группа. После 12-й тренировки автоматически начинается новый блок со следующим номером.
2. **Журнал рабочих весов.** Упражнения сгруппированы по группам мышц. Каждая запись содержит упражнение, вес и дату. По каждому упражнению строится график роста веса.

**Доступ:**
- чтение открыто всем, у кого есть ссылка (в том числе тренеру);
- запись разрешена только владельцу, которого определяет Telegram ID.

## 2. Стек

| Слой | Технология |
|---|---|
| Фронт | Vite + React + TypeScript, `telegram-web-app.js`, Chart.js (`react-chartjs-2`) |
| Хостинг | Firebase Hosting (в существующем GCP-проекте) |
| БД | Cloud Firestore, регион `asia-southeast1` |
| Запись | Cloud Functions for Firebase (2nd gen), Node 22, TypeScript |
| Проверка Telegram | `@tma.js/init-data-node` (или собственная реализация HMAC, см. §5) |
| Бот | Новый бот через BotFather, используется только как точка входа в Mini App |

Требования: тариф Blaze в GCP-проекте. На таких объёмах расходы укладываются в бесплатные лимиты.

## 3. Архитектура

```
Telegram (владелец / тренер)
        │  открывает t.me/<bot>/app
        ▼
Firebase Hosting ── статический фронт
        │
        ├── чтение ──► Firestore (rules: read = true)
        │
        └── запись ──► Cloud Function `api`
                          ├─ проверка подписи initData
                          ├─ user.id == OWNER_TELEGRAM_ID ?
                          └─ запись через Admin SDK (транзакции)
```

- Клиент никогда не пишет в Firestore напрямую: `allow write: if false`.
- Вся бизнес-логика (номер блока, следующая группа) выполняется на сервере внутри транзакции.
- Вне Telegram (в обычном браузере) приложение открывается в режиме только чтения.

## 4. Модель данных (Firestore)

### `config/main` (один документ)
```ts
{
  groups: [
    { id: "back",      title: "Спина" },
    { id: "chest",     title: "Грудные" },
    { id: "legs",      title: "Ноги" },
    { id: "arms",      title: "Бицепс / трицепс" },
    { id: "shoulders", title: "Плечи" }
  ],              // порядок = порядок ротации
  blockSize: 12,
  timezone: "Asia/Bangkok"
}
```

Порядок выше — не произвольный пример, а реальный порядок владельца gym-tracker-tg, подобранный
разбором истории тренировок (см. [stage-1-workouts.md](stage-1-workouts.md), раздел «Реальный
порядок ротации и импорт истории»). Для другого владельца порядок может быть другим — это
конфигурация, а не константа приложения.

### `state/workouts` (счётчики, изменяются только в транзакции)
```ts
{
  totalCount: number,      // всего тренировок
  currentBlockNo: number,
  countInBlock: number,    // 0..12
  lastGroupId: string | null
}
```

### `workouts/{autoId}`
```ts
{
  date: "YYYY-MM-DD",      // локальная дата в config.timezone
  groupId: string,
  blockNo: number,
  posInBlock: number,      // 1..12
  seq: number,             // глобальный порядковый номер, 1..N
  createdAt: Timestamp
}
```

### `exercises/{autoId}`
```ts
{
  name: string,
  groupId: string,
  archived: boolean,
  createdAt: Timestamp,
  // денормализация для быстрого списка:
  lastWeight?: number,
  lastDate?: "YYYY-MM-DD"
}
```

### `weightLogs/{autoId}`
```ts
{
  exerciseId: string,
  groupId: string,         // денормализация
  date: "YYYY-MM-DD",
  weight: number,          // кг, шаг 0.5
  reps?: number,           // опционально
  note?: string,
  createdAt: Timestamp
}
```

**Индексы:** composite-индекс `weightLogs (exerciseId ASC, date ASC)`. Запрос `workouts (seq DESC)` по одному полю покрывается автоматическим single-field индексом Firestore — отдельный composite-индекс для него Firestore отклоняет как избыточный.

## 5. Бизнес-логика

### Следующая группа
Следующая группа определяется **от последней фактической группы**, а не формулой `totalCount % 5`. Благодаря этому ручная смена группы тренером не ломает очередь.
```
nextIndex = lastGroupId == null ? 0 : (indexOf(lastGroupId) + 1) % groups.length
```
Порядок ротации групп мышц настраивается в интерфейсе (экран «Порядок групп», §8) через action `updateConfig`. По сути это порядок `groups` в `config/main`.
Смена порядка не трогает `state.lastGroupId`: следующая группа вычисляется по формуле выше уже в новом порядке. Если `lastGroupId` в новом списке отсутствует (группу удалили), следующей считается первая группа.

### Блок
```
if countInBlock == blockSize → currentBlockNo += 1, countInBlock = 0
countInBlock += 1  → posInBlock
```
Граница блока и ротация групп независимы: 12 не кратно 5, поэтому ротация продолжается через границу блока.

### Undo последней тренировки
Удаляется документ с максимальным `seq`. Затем `state` пересчитывается по новой последней записи: `lastGroupId`, `currentBlockNo`, `countInBlock`, `totalCount`. Удалять разрешено только последнюю тренировку.

### Смена группы у последней тренировки
Обновляется `groupId` у последней записи и `state.lastGroupId`. Для более старых записей смена группы на очередь не влияет, поэтому её можно разрешить для любой записи, но `state` обновляется только если это последняя.

### Проверка initData (Cloud Function)
1. Клиент отправляет заголовок `Authorization: tma <Telegram.WebApp.initData>`.
2. Парсим строку как query string и извлекаем `hash`.
3. `data_check_string` — все остальные пары `key=value`, отсортированные по ключу и объединённые через `\n`.
4. `secret = HMAC_SHA256(key="WebAppData", msg=BOT_TOKEN)`.
5. Сравниваем `hex(HMAC_SHA256(key=secret, msg=data_check_string))` с `hash` через constant-time compare.
6. Проверяем свежесть: `now - auth_date < 24h`.
7. Проверяем, что `JSON.parse(user).id == OWNER_TELEGRAM_ID`, иначе возвращаем `403`.

Рекомендуется использовать готовую библиотеку `@tma.js/init-data-node` (`@telegram-apps/init-data-node` — deprecated, тот же автор перенёс пакет), чтобы не ошибиться с деталями формата (в том числе с полем `signature`). `validate(initDataRaw, botToken)` бросает исключение на невалидной подписи или протухшем `auth_date` (по умолчанию `expiresIn: 86400` — как раз требуемые 24ч), `parse(initDataRaw)` отдаёт типизированный объект с `user`.

### Даты
Сервер вычисляет «сегодня» в `config.timezone`. Клиент может передать `date` явно, если нужна запись задним числом.

## 6. API Cloud Function

Одна HTTPS-функция `api` (`onRequest`, регион `asia-southeast1`, CORS для домена Hosting). Все запросы отправляются как `POST` с телом `{ action, payload }`.

| action | payload | Результат |
|---|---|---|
| `addWorkout` | `{ date?, groupId? }` | созданная тренировка + новый state |
| `undoLastWorkout` | — | новый state |
| `setWorkoutGroup` | `{ workoutId, groupId }` | обновлённая запись |
| `addExercise` | `{ name, groupId }` | exercise |
| `updateExercise` | `{ id, name?, archived? }` | exercise |
| `addWeight` | `{ exerciseId, weight, reps?, date?, note? }` | log (+ обновление `lastWeight/lastDate`) |
| `deleteWeight` | `{ id }` | ok (+ пересчёт `lastWeight/lastDate`) |
| `seed` | `{ currentBlockNo, countInBlock, lastGroupId }` | state (начальная инициализация, см. §10) |
| `updateConfig` | `{ groups?, blockSize?, timezone? }` | обновлённый `config/main` (порядок групп, §5) |
| `whoami` | — | `{ isOwner: boolean }` |

**Секреты и параметры:**
- `BOT_TOKEN` задаётся через `defineSecret` (`firebase functions:secrets:set BOT_TOKEN`);
- `OWNER_TELEGRAM_ID` задаётся через `defineString`.

Валидация входных данных выполняется через zod.

## 7. Firestore Security Rules

```
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    match /{document=**} {
      allow read: if true;
      allow write: if false;
    }
  }
}
```

⚠️ Это осознанное решение: данные читаемы любым, у кого есть конфиг проекта или ссылка.

## 8. UI

Референс — мокапы в `spec/mockup/`:

| Файл | Экран |
|---|---|
| `Screenshot 2026-09-19 at 16.30.35.png` | Тренировки |

Общие требования:
- тема берётся из `Telegram.WebApp.themeParams` (CSS-переменные);
- при запуске вызываются `ready()` и `expand()`;
- при успешной записи срабатывает `HapticFeedback`;
- режим владельца включается по ответу `whoami`. Для остальных кнопки записи, шапочные иконки `+` / `✎` / `···` и меню владельца скрыты (это косметика, защита реализована на сервере);
- **`MainButton` не используется.** Главное действие экрана — обычная кнопка во всю ширину внутри страницы, закреплённая над нижним таб-баром (акцентный цвет `button_color`, скруглённая — как на мокапах). Причина: `MainButton` прижимается к низу окна и конфликтует с таб-баром, а на экране «Упражнение» нужна собственная первичная кнопка «Сохранить». `BackButton` Telegram при этом используется (см. «Навигация»);
- у приложения собственная шапка: слева «Закрыть» (или «‹ Назад» на вложенном экране), по центру заголовок, справа контекстное действие экрана.

### Экран «Тренировки» (главный)
- Шапка: заголовок «Gym tracker», справа `···` — меню владельца: «Порядок групп», «Инициализация данных», «Экспорт CSV» (см. §10, §12, этап 4).
- Карточка текущего блока: «Блок №N», справа «k из 12», под ними progress bar.
- Бейдж «Осталось 2 / 1 тренировки в блоке», когда `12 - k ≤ 2` (предупреждающий цвет, как на мокапе).
- Карточка «Следующая: **Плечи**» со стрелкой.
- Список тренировок: текущий блок раскрыт, строки «#pos · группа» слева и дата справа, новые сверху. Предыдущие блоки — свёрнутые строки «Блок №N · 12 тренировок» с шевроном.
- **Первичная кнопка «Отметить тренировку»** над таб-баром. Один тап отправляет `addWorkout`.
- После успеха — toast снизу на 5 с с кнопкой «Отменить» (вызывает `undoLastWorkout`) и ссылкой «Внести веса → [группа]» (переход на экран «Веса» с выбранной группой только что отмеченной тренировки).
- Долгий тап по строке тренировки (только владелец) открывает меню: «Изменить группу» (`setWorkoutGroup`) и — только для последней записи — «Удалить» (`undoLastWorkout`). Это запасной путь к undo после того, как toast исчез.

### Экран «Веса»
- Шапка: заголовок «Веса», справа иконка `+` — добавление упражнения в текущую группу (только владелец); открывает модалку с полем «Название».
- Фильтр по группам — чипы (не табы), переносятся на две строки, активный чип залит акцентным цветом. Порядок чипов = порядок `config.groups`.
- Список упражнений группы: название, под ним дата последней записи мелким шрифтом, справа крупно последний вес (`lastWeight` / `lastDate`). Архивные скрыты.

### Экран «Упражнение»
- Шапка: «‹ Назад», название упражнения, справа иконка `✎` — модалка «Переименовать» / «Архивировать» (только владелец).
- График в отдельной карточке: ось X — дата, ось Y — вес (Chart.js, line, time scale). Если в данных есть повторения, добавляется переключатель «вес / расчётный 1ПМ» (Epley: `w * (1 + reps/30)`), этап 3.
- Блок «Новая запись · сегодня»: кнопки `−2.5` и `+2.5` по краям, между ними крупное значение веса (предзаполнено последним), ниже поле «Повторения (необязательно)». Тап по слову «сегодня» открывает выбор даты — запись задним числом (см. §5 «Даты»).
- История записей, новые сверху: «90 кг × 8» и дата справа. Без `reps` строка выглядит как «90 кг». Удаление — свайп по строке или долгий тап (`deleteWeight`).
- Первичная кнопка «Сохранить» над таб-баром.

### Экран «Порядок групп» (владелец)
Список групп из `config.groups` с перетаскиванием (drag handle). Сохранение — `updateConfig`. Изменение порядка не меняет `state.lastGroupId`, поэтому следующая группа пересчитывается сразу по новому порядку (§5).

### Экран «Инициализация» (владелец)
Одноразовый экран для `seed` и для ввода уже проведённых блоков — см. §10 (этап 1) и §12.

### Навигация
Нижний таб-бар «Тренировки / Веса» (иконки + подпись, активный — акцентным цветом) и `BackButton` Telegram на вложенных экранах. Таб-бар виден на всех экранах, включая «Упражнение».

### Режим «только чтение» (тренер)
Тот же набор экранов без: первичных кнопок, блока «Новая запись», иконок `+` / `✎` / `···`, долгих тапов и toast. Шапка и списки идентичны.

## 11. Критерии приёмки

- Один тап по кнопке «Отметить тренировку» создаёт тренировку с сегодняшней датой (Asia/Bangkok) и правильной следующей группой.
- 13-я тренировка получает `blockNo + 1` и `posInBlock = 1`.
- После undo очередь и счётчики возвращаются в предыдущее состояние.
- Тренер, открыв ссылку, видит журнал и графики, но не видит кнопок записи.
- Прямой запрос к функции без валидного initData или с чужим ID возвращает `403`.
- Прямая запись в Firestore с клиента отклоняется правилами.
- График упражнения отображает все записи в хронологическом порядке.
- Изменение порядка групп в интерфейсе сразу меняет «Следующая: …» и не сбрасывает очередь.
- Undo доступен и из toast, и из долгого тапа по последней тренировке.
