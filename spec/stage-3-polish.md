## Проверенные факты (важны для реализации)

- **Canvas не понимает CSS-переменные.** `var(--tg-theme-button-color)` в опциях Chart.js не
  отрисуется: цвета в canvas — это строки, которые парсит сам Chart.js. Значения берём
  `getComputedStyle(document.documentElement).getPropertyValue('--tg-theme-button-color').trim()`
  и передаём в датасет числом/строкой цвета.
- **Chart.js 4 без адаптера дат не умеет `type: 'time'`** — падает на первом рендере. Нужен
  `chartjs-adapter-date-fns` (3.0.0, peer `date-fns >= 2.0.0`) + `date-fns` (4.4.0).
- Версии на момент планирования: `chart.js` 4.5.1, `react-chartjs-2` 5.3.1 (peer `react ^19` —
  с текущим React 19.2 совместим), `@dnd-kit/core` 6.3.1, `@dnd-kit/sortable` 10.0.0.
- Telegram сам инжектит переменные `--tg-theme-*` в `:root` (Bot API 6.1+): `bg_color`,
  `text_color`, `hint_color`, `link_color`, `button_color`, `button_text_color`,
  `secondary_bg_color` и более новые `section_bg_color`, `destructive_text_color`. **Вне Telegram
  их нет** — каждое использование пишем с фолбэком: `var(--tg-theme-bg-color, #17212b)`.
- `HapticFeedback`, `setHeaderColor`, `setBackgroundColor` появились в Bot API 6.1: на старом
  клиенте обращение к ним бросает исключение. Проверяем `WebApp.isVersionAtLeast('6.1')` и
  оборачиваем в no-op.
- Смена темы прилетает событием `WebApp.onEvent('themeChanged', cb)`; CSS-переменные Telegram
  обновляет сам, а вот график нужно перекрасить вручную (см. первый пункт).

## Принятые решения

1. **Chart.js регистрируем поэлементно, без `chart.js/auto`.** Нужны `LineController`,
   `LineElement`, `PointElement`, `LinearScale`, `TimeScale`, `Tooltip`, `Filler`. Импорт `auto`
   тянет все типы графиков в бандл ради одного line chart.
2. **Ось X — `type: 'time'`, а не категории.** Записи неравномерны по времени (§1: тренировки идут
   с паузами), и на категориальной оси месячный простой выглядит как обычный шаг. Цена — адаптер
   дат; альтернатива (линейная шкала по миллисекундам с `ticks.callback`) отклонена: сама
   расстановка «май … сен», как в мокапе, придётся писать руками.
3. **1ПМ — формула Эпли `w * (1 + reps / 30)` (§8).** Переключатель показывается, только если хотя
   бы у одной записи упражнения есть `reps`. Записи без `reps` в режиме 1ПМ рисуем как есть: Эпли
   при `reps = 1` даёт `w * 1.033`, то есть практически тот же вес, и выдумывать точность, которой
   нет в данных, смысла нет.
4. **Тема — только CSS-переменные Telegram, без своего JS-объекта темы.** Один источник правды;
   JS читает переменные лишь там, где нужен canvas (решение 1) и `setHeaderColor`. Все цвета
   приложения объявляются в `index.css` через `var(--tg-theme-*, <фолбэк>)`.
5. **`updateConfig` не даёт менять набор групп — только порядок и `title`.** Если во входящем
   `groups` набор `id` отличается от текущего, отвечаем `400`. Причина: `groupId` денормализован в
   `workouts`, `exercises` и `weightLogs`; удаление группы осиротит эти документы, а UI для
   добавления/удаления в §8 не описан (там только перетаскивание). `blockSize` и `timezone` схема
   принимает (§6), но экрана для них в этом этапе нет.
6. **Drag & drop — `@dnd-kit` (core + sortable).** HTML5 drag-and-drop в мобильном WebView
   нерабочий, а `@dnd-kit` построен на pointer events и умеет `activationConstraint`, чтобы
   перетаскивание не конфликтовало со скроллом списка. Нулевой по зависимостям вариант — кнопки
   «↑ / ↓» вместо ручки — оставляем как запасной, если dnd-kit окажется тяжёлым для одного экрана.
7. **Тест-раннер в `web/` не заводим.** Единственная новая чистая функция на клиенте — Эпли в три
   строки; она проверяется по DoD вручную. Vitest в вебе имеет смысл заводить вместе с первым
   нетривиальным клиентским доменным модулем, не раньше.

### `domain/groups.ts`

```ts
export interface Group { id: string; title: string }

// Same set of ids, order ignored (decision 5).
export function sameGroupIds(current: Group[], next: Group[]): boolean;

// Duplicate ids or blank titles make the update invalid.
export function findGroupsProblem(next: Group[]): string | null;
```

Тесты (`groups.test.ts`): тот же набор в другом порядке → `true`; убрали группу → `false`;
добавили новую → `false`; дубликат `id` → проблема; пустой `title` → проблема; пустой массив →
проблема.

### `schemas.ts`

```ts
export const updateConfigSchema = z.object({
  groups: z.array(z.object({
    id: z.string().min(1),
    title: z.string().trim().min(1).max(40),
  })).min(1).optional(),
  blockSize: z.number().int().min(1).max(100).optional(),
  timezone: z.string().min(1).optional(),
});
```

### `actions/updateConfig.ts`

Транзакция:
1. `t.get(configRef)` → нет документа → `500` (его создаёт бутстрап-скрипт этапа 1).
2. Если пришёл `groups`: `findGroupsProblem` → `400` с текстом; `sameGroupIds(current, next)` →
   `false` → `400` (решение 5).
3. `t.update(configRef, { ...groups?, ...blockSize?, ...timezone? })`.
4. Вернуть обновлённый `config/main`.

`state/workouts` не трогаем вообще — это и есть требование §5: порядок сменился, `lastGroupId`
остался, следующая группа пересчитывается уже по новому порядку.

### График

`WeightChart.tsx` получает уже загруженные `weightLogs` (их читает экран «Упражнение» с этапа 2,
запрос `exerciseId ==` + `orderBy date asc` — существующий индекс §4).

- датасет: `{ x: Date.parse(log.date), y: mode === 'weight' ? log.weight : epley(log.weight, log.reps) }`;
- `scales.x`: `type: 'time'`, `time.unit: 'month'`, подписи — короткий месяц (как «май … сен» в
  мокапе); `scales.y`: `beginAtZero: false`;
- цвета линии, точек и сетки — через `readThemeColor` (решение 1 + факт про canvas);
- подписка `onThemeChanged` → перечитать цвета и обновить график;
- переключатель «вес / 1ПМ» — сегмент-контрол над графиком, виден только если
  `logs.some(l => l.reps != null)` (решение 3);
- одна запись — точка без линии; ноль записей — вместо графика `EmptyState`, карточка не пустая.

### Haptics

`lib/haptics.ts` — тонкие обёртки, каждая молча ничего не делает вне Telegram и на клиенте старше
6.1 (см. «Проверенные факты»):

- успешная запись (`addWorkout`, `addWeight`, `addExercise`) → `notificationOccurred('success')`;
- ошибка любого action → `notificationOccurred('error')`;
- смена чипа группы и вкладки таб-бара → `selectionChanged()`;
- `−2.5` / `+2.5` в степпере → `impactOccurred('light')`.

### Пустые состояния и скелетоны

| Место | Пусто | Загрузка |
|---|---|---|
| «Тренировки», список | «Пока нет тренировок» + подсказка про кнопку | 3 строки-скелетона + карточка блока |
| «Веса», список группы | «В этой группе пока нет упражнений» | 4 строки-скелетона |
| «Упражнение», история | «Пока нет записей» (вместо графика тоже) | карточка графика + 2 строки |

Скелетон повторяет высоту реальной строки, чтобы список не прыгал при подстановке данных; анимация
— один CSS-шиммер в `Skeleton.tsx`, без библиотек.

### Меню владельца и экран «Порядок групп»

`···` в шапке «Тренировок» (только владелец) открывает меню с единственным пунктом «Порядок групп»
(остальные пункты §8 — в более поздних этапах, см. «Что не входит»).

`GroupOrder.tsx` — вложенный экран поверх вкладки «Тренировки», `BackButton` как на «Упражнении»:

- список `config.groups` с ручкой перетаскивания (`@dnd-kit/sortable`, `PointerSensor` с
  `activationConstraint: { delay: 150, tolerance: 5 }`, чтобы обычный скролл не начинал drag);
- «Сохранить» → `postApi('updateConfig', { groups })` → рефетч `config/main` → возврат назад;
- карточка «Следующая: …» на «Тренировках» после возврата показывает новую группу — это и есть
  критерий §11, поэтому config перечитывается, а не патчится локально.

### Toast «Отменить»

Расширение компонента из этапа 2: две зоны — «Отменить» (вызывает `undoLastWorkout`, затем
рефетч state и списка) и ссылка «Внести веса → [группа]». Таймер на 5 с, `clearTimeout` при
размонтировании и при показе нового toast; после нажатия «Отменить» toast закрывается сразу, не
дожидаясь таймера. Повторный тап по «Отменить» блокируется на время запроса, иначе второй запрос
удалит уже следующую тренировку.

### Свайп-удаление записи веса

Перенесено из этапа 2 (§8, экран «Упражнение»): горизонтальный свайп по строке истории открывает
«Удалить» → подтверждение → `deleteWeight`. Долгий тап остаётся как альтернативный путь.
Реализация на pointer events, без библиотеки; порог ~40 px, вертикальное движение отменяет жест.

## Риски и на что смотреть

| Риск | Что делать |
|---|---|
| График остаётся в старых цветах после смены темы | подписка на `themeChanged` + перечитывание через `getComputedStyle`; проверять переключением темы в Telegram Desktop |
| Забыт импорт `chartjs-adapter-date-fns` | ось времени падает на первом рендере; адаптер импортируется ради побочного эффекта — линтер может счесть импорт неиспользуемым, не удалять |
| Drag конфликтует со скроллом списка | `activationConstraint` у `PointerSensor`; проверять на реальном телефоне, не в десктопном браузере |
| `updateConfig` осиротит `groupId` в трёх коллекциях | защищено `sameGroupIds` → `400` (решение 5); при появлении UI добавления групп сначала продумать миграцию документов |
| Двойное нажатие «Отменить» удаляет две тренировки | кнопка блокируется на время запроса; проверить ручным быстрым двойным тапом |
| `HapticFeedback` на старом клиенте бросает исключение | все вызовы через `lib/haptics.ts` с `isVersionAtLeast('6.1')` и try/catch |
| Светлая тема Telegram ломает контраст (всё рисовалось под тёмную из мокапов) | пройти все экраны в светлой теме; фолбэки в `index.css` не должны «просвечивать» внутри Telegram |
| Скелетоны мигают на быстрой сети | допустимо; если раздражает — показывать скелетон только если загрузка длится дольше ~200 мс |
